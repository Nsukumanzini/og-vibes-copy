# OG Vibes six-digit signup rollout

The student and staff applications now verify new accounts with the same six-digit code generated by Supabase Auth. This removes confirmation links from the signup email, so Brevo click tracking cannot rewrite the signup confirmation action.

## Supabase settings required before deployment

1. Open **Authentication > Providers > Email**.
2. Keep **Confirm email** enabled.
3. Set **Email OTP length** to **6**. The student and staff interfaces intentionally accept exactly six digits.
4. Keep **Email OTP expiration** at 3600 seconds for the first supervised rollout, or shorten it later after the flow is proven stable.
5. Open **Authentication > Email Templates > Confirm signup**.
6. Set the subject to **Confirm your OG Vibes account**.
7. Replace the template body with the complete contents of `docs/student-confirmation-email-template.html`.
8. Save the template and confirm that the saved body contains `{{ .Token }}` and does not contain `{{ .ConfirmationURL }}`.
9. Open **Authentication > Rate Limits** and set the email-per-hour allowance high enough for the supervised group, without exceeding the Brevo daily allowance.

The hosted Supabase project has one Confirm signup template. The same template therefore serves both student and lecturer signups.

## Acceptance test before distribution

Use new email addresses that have never registered before.

### Student

1. Create a student account.
2. Confirm that the app immediately opens the six-digit verification screen.
3. Confirm that the Brevo email contains a code and no confirmation button or fallback confirmation URL.
4. Enter a wrong code and confirm that access is rejected.
5. Enter the correct code and confirm that the welcome animation opens the student feed.
6. Confirm in **Authentication > Users** that **Email confirmed at** is populated.
7. Confirm that the student's nickname, programme and level appear in the profile.

### Lecturer

1. Create a lecturer account on the staff website.
2. Confirm that the website opens `/verify-email` and requests the code.
3. Enter the correct code and confirm that the lecturer is signed out and shown the pending-approval page.
4. Confirm that the admin console shows the lecturer application.
5. Approve the lecturer, then confirm that the lecturer can sign in to the staff dashboard.

### Delivery and recovery

1. Use **Send a new code** once and confirm that Brevo delivers a replacement code.
2. Delete or ignore every earlier email: requesting a replacement invalidates the previous code. Confirm that the newest code succeeds.
3. Check **Brevo > Transactional > Logs** for delivered, deferred, bounced or blocked messages.
4. Test password recovery separately because recovery emails still use a secure recovery link.

Do not distribute the applications until both the student and lecturer acceptance tests pass on the production Supabase project.
